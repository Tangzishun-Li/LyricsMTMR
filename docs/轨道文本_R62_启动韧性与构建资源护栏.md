## §4 契约

### 4.1 r62-a 启动步骤三档划分（行为对外等价，只挪时序）

| 档 | 步骤（AppDelegate.swift 行号） | 理由 |
|----|------|------|
| MAIN_IMMEDIATE | AX 权限检查(:35) → TouchBarController.setupControlStripPresence(:38) → reloadStandardConfig(:41)；statusItem/setupPopover(:44-50) | 顺序强约束见源注释 :39-40；Touch Bar 内容与状态栏必须首帧就绪 |
| MAIN_NEXT_TICK | LyricsEngine.start(:59)、SlotManager.ensureSlotsDirectory(:60)、桌面歌词条件恢复(:63-67) | 非 Touch Bar 主链路，下一个 runloop tick 执行 |
| BACKGROUND | HapticFeedback.scanAllDeviceIDs(:37) | 蓝牙全量扫描，最慢且零 UI 依赖 |

另：DISPATCH_SOURCE_TYPE_MEMORYPRESSURE CRITICAL 监听，触发时复用既有清理链
（applicationDidReceiveMemoryWarning :82-92 抽公共函数）+ os_log 一行。

### 4.2 r62-b 锁脚本接口

`sh scripts/build-with-lock.sh <xcodebuild 原命令…>`；锁文件默认 `/tmp/lyricsmtmr-build.lock`
（env MTMR_BUILD_LOCK 可覆盖）；并发等待每 30s 打一行提示；注入 `-jobs $MTMR_BUILD_JOBS`（缺省 4）
与 `COMPILER_INDEX_STORE_ENABLE=NO`（命令已含则不重复加）；退出码透传；bash 3.2 兼容
（禁关联数组；set -u 下 `${}` 包裹变量防多字节误报）。

### 4.3 r62-d 调研边界

只产报告不改码；外部结论必带 URL 出处；对本仓建议必带 grep 文件:行号 取证。

## §5 验收总则

1. 每执行卡：增量构建 SUCCEEDED（能用锁脚本则走锁脚本）+ 自己新增套件全绿 + 受影响套件 0 失败。
2. r62-a 金标准：StartupSequenceTests 断言 §4.1 三档分区与相对顺序（注入调度器，不依赖真实硬件）；
   BACKGROUND 档不含任何 UI 步骤。
3. r62-b 金标准：两进程并发实测互斥（总时长≈两者之和）；`bash -n` 干净；无参调用给用法退出非 0。
4. INTEG 里程碑测试（用户点名，优先于隔代规则）：整体构建 + **全量回归一次 0 失败** +
   版本顺延一版（以 main 当时版本 +1）+ 简报三件套 + 速查表滚动 + 报告归档 `logs/第62轮/` +
   file-structure 登记 + 锚点巡检 0 ERROR + push main。

## §7 迭代节奏红线（结构性决定）

- **并行的是「开发」，串行的是「构建」**：本轮执行卡刻意少而精（2 代码 + 1 调研），因为
  多 worker 并发构建就是 §1 病灶本身；后续轮次开更多分析/文档/决策卡不受限，
  但一切 xcodebuild 必须经锁脚本。
- 用户红线：不许牺牲流畅度与体验（本轮 a 卡目标是改善而非妥协）；破坏性操作先报备。
