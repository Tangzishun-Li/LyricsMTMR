# 空闲性能与能耗基线

> 计划板第 5 条（P1 · 质量护栏）。目标：默认预设在空闲时不该出现"CPU 常亮 / 内存缓慢上涨 /
> 每秒被定时器叫醒几十次"的回归。

## 1. 怎么测

```bash
# 构建 Release + 采样 60s（默认每 5s 一次）
python3 LyricsMTMR/Scripts/measure_idle.py --build

# 只测已构建的 App
python3 LyricsMTMR/Scripts/measure_idle.py --app /path/to/LyricsMTMR.app

# 用本次实测重写阈值（会留余量）
python3 LyricsMTMR/Scripts/measure_idle.py --build --update-baseline

# 只比对、不重新测：CI 用同一条命令
python3 LyricsMTMR/Scripts/measure_idle.py --app ... --json-out /tmp/idle.json
```

测量口径（脚本里也写了）：

1. 用**临时 `HOME`** 启动，保证跑的是仓库默认预设，而不是本机 `~/Library` 里的配置；
2. 启动后 **10s 预热**，把启动期的一次性工作排除；
3. 每 5s 采一次：`top -l 2 -stats pid,cpu,idlew` 取第二次（瞬时）采样，`ps -o rss=` 取常驻内存；
4. 持续 60s，CPU 取平均、内存取峰值、idle wakeups 取平均；
5. 任一指标超过 `Scripts/idle-baseline.json` 即退出码 1。

> 为什么 idle wakeups 低：`TouchBarVisibilityState` 在 bar 隐藏时会暂停所有轮询组件
> （round 18 的 pause 机制）。所以这台机器上测到的是"bar 隐藏 + 默认预设"的真实空闲，
> 这也是用户插电挂机时最常见的工作状态。

## 2. 当前基线（2026-11-16，macOS 15.8.3 arm64）

| 指标 | 实测 | 阈值（留余量） |
| --- | --- | --- |
| CPU 平均 | 0.2% | ≤ 3.0% |
| CPU 峰值 | 1.3% | 仅记录 |
| 内存峰值 | 60.3 MB | ≤ 200 MB |
| idle wakeups 平均 | 2.7 | ≤ 20 |

阈值在 [`LyricsMTMR/Scripts/idle-baseline.json`](../LyricsMTMR/Scripts/idle-baseline.json)。

## 3. CI 里怎么跑

- 工作流：`.github/workflows/perf-baseline.yml`
- 触发：每周一 02:23 UTC（约北京时间周一 10:23）+ 手动 `workflow_dispatch`
- 产物：每次都会上传 `idle.json`（失败也传），用于对比历史
- 超预算 → job 红；同时能看到具体是哪一项

## 4. 已知局限

- 只在 macOS runner 上测"bar 隐藏"状态；**bar 常显时的轮询开销**没有覆盖（需要真机 + 可见 Touch Bar）。
- CI 机器性能与用户机器不同，阈值故意留了 1.5×~2× 余量；这条线的作用是抓"数量级回归"（例如某个轮询从 1s 变 0.1s、或某个组件忘了 pause），不是精确性能承诺。
- 首次在慢速 runner 上跑可能偏紧，届时用 `--update-baseline` 在稳定的 runner 上重测并提交。
