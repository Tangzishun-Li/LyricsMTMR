## 用户原始需求（逐字记录，不可丢失）

> 以下内容由用户在 2026-09-14 提出，是整个编辑器重构的出发点。
> 后续任何阶段的设计和实现都必须回溯这里，确保没有偏离。

### 问题一：接口不固定
现在的编辑器"该编辑的地方它没有，不该编辑的它就乱搞"。
- 编辑器暴露的字段和实际 ItemType 枚举对不上
- 有些 widget 的关键参数编辑器不显示
- 有些不该暴露的内部字段却出现在编辑器里

### 问题二：无法热更新
没有办法在编辑器里"试一下"新组件的效果。
- 当前修改 JSON 后需要重启 app 才能看到变化
- 希望能在编辑器里实时预览、即时生效

### 问题三：无法加载正在使用的主题
编辑器打开是空白的，不能把当前正在使用的主题加载进来编辑。

### 问题四：无法创建草稿主题
用户习惯用主题切换功能（themeSwitch widget），想在编辑器里：
- 创建一个全新的"主题 7"
- 在已有的"主题 2"和"主题 3"之间插入一个新主题
- 编辑好之后保存，不影响当前正在使用的主题

### 问题五：可视化功能不够到位
希望在电脑屏幕上有一个和 Touch Bar 完全一样的显示区域：
- **目的**：用户在 MacBook 上很少用鼠标，希望能在屏幕上用触控板操作 Touch Bar 内容
- **尺寸**：横条高度 30px，M1 MacBook Pro 2020，Touch Bar 物理分辨率约 2170×60 @2x
- **先做镜像**：先把 Touch Bar 上能显示的东西原封不动搬到屏幕上
- **再做编辑**：在镜像基础上实现拖拽、增删、调整顺序等编辑操作

### 问题六：内存占用
希望设置界面在不使用时几乎不占用内存：
- 没调出设置时 → 基本不占内存
- 调出设置时才加载

### 2026-09-14 补充需求（第二批）

#### 需求 7：内置 JSON 文本编辑器
还需要一个 JSON 文件的编辑器。不想去调 Xcode 或者 VSCode 了，直接内置一个文本编辑器就行。

#### 需求 8：小组件选项的归类与展示
现在所有小组件都是横排选项，已经有 99、100 个了，太多了，完全排不过来，要划拉很久才能找到想要的东西。

**(a) 分组归类**：应该做一个下拉栏进行归类，大概分个五六个或七八个组。

**(b) 图标与示例渲染**：每个组里面要包括小组件的"图标加文字"。
- 是**图标**，不是 emoji！
- 既然能把它渲染在 Touch Bar 上，就不信没办法把它渲染成一个 example 出来
- 在下拉栏里就能看到这个渲染出来的 example，选一下，然后拉到模拟的 Touch Bar 上

#### 需求 9：更新机制
**(a) 热更新**：如果选择可以热更新，那它就可以同步显示在我的 Touch Bar 上。

**(b) 非热更新**：如果选择不热更新，那么当我编辑完以后，选择更新，它也会显示在我的 Touch Bar 上。

#### 需求 10：可视化编辑功能缺陷
比如把某个小组件拖入编辑器进行设置时，里面的选项竟然奇奇怪怪的。
- 正儿八经的小组件在 JSON 编辑器里能设置的东西，在这个可视化编辑器里面竟然设置不了
- 可视化编辑器里的设置是乱的，甚至有些地方上面写着"编辑"，但其实没有办法实际更改文件

#### 需求 11：JSON 智能校验机制
既然是可视化了，就要考虑：如果需要对照文件，肯定要有文件的智能写法。
- 如果可能会产生 syntax error，或者生成的 JSON 不太对，要有校验机制

#### 需求 12：ThemeSwitch 智能联动
往里面加主题的话，不太想自己去调 switch 的 JSON 文件：
- 比如有 7 个预设，switch 就应该有 7 个可以选择的 case
- 不应该自己去打开 7 个文件加第 7 个 case
- 编辑器应该自动整理好：创建了第 7 个预设，switch 自动获得第 7 个选项
- 如果在 2 和 3 之间加了一个，switch 里也应该自动加到 2 和 3 之间，其他的自动挪到后面

#### 需求 13：所有常用 widget 的接口必须正确
将近 100 个 item，除掉一些生活之类的，比较原始的、用量比较多的（现在 6 个预设里面的小组件），都是比较刚需的。这些都要把接口做好。

### 现存问题详析

#### 问题 1：Palette 水平滚动（99 个 widget 全部平铺）

**当前代码**（RibbonEditorView.swift:1919-1984）：
```swift
struct PaletteRibbon: View {
    ScrollView(.horizontal, showsIndicators: false) {
        HStack(spacing: 0) {
            ForEach(filteredCategories) { category in
                HStack(spacing: 4) {
                    ForEach(category.types) { type in
                        PaletteChip(schema: schema)  // 50×38pt，SF Symbol + 文字
                    }
                }
                Divider()  // 竖线分隔
            }
        }
    }
}
```

**问题**：18 个分类 × 5-10 个 chip = 99 个 chip 水平排开，要划很久。
**方案**：改为可折叠分组 + 渲染预览图。

#### 问题 2：ThemeSwitch 悬空引用

**现状**：
- `items.json` 和 `theme4.json` 的 themeSwitch 引用了 theme7~15.json
- 但磁盘上**只有 theme1~6.json**！theme7~15.json 不存在！
- `ensureThemeSwitchLists(in:)` 会过滤掉不存在的 preset（DraftManager.swift:112）
- 所以每次 save 都会把 theme7~15 从 themes 数组里删掉
- 但下一次编辑又会重新从 items.json 读入，恢复悬空引用

**数据**：
| 文件 | themeSwitch 条目数 | 实际存在 |
|------|-------------------|---------|
| items.json | 15 (theme1~15) | 只有 1~6 |
| theme1.json | 6 (theme1~6) | ✅ |
| theme2.json | 6 (theme1~6) | ✅ |
| theme3.json | 6 (theme1~6) | ✅ |
| theme4.json | 15 (theme1~15) | 只有 1~6 |
| theme5.json | 6 (theme1~6) | ✅ |
| theme6.json | 6 (theme1~6) | ✅ |

**方案**：创建 theme7~15.json（从 DraftManager 创建），或清理悬空引用。

#### 问题 3：Mirror 只读不可编辑

**当前代码**（TouchBarMirrorWindowController.swift）：
- `show()` 创建 NSPanel，底部居中，800pt × 34pt
- `syncFromTouchBar()` 增量同步：指纹比对 + 脏标记 + 快照节流

private func syncToTouchBar() {

### 补充 2：内存架构详情

**SettingsTabCache**（LRU 缓存，容量 4）：
- 最多缓存 4 个 tab 的 AnyView
- 最久未用的 tab 自动驱逐
- 编辑器 tab 被驱逐后下次进入重建

**SettingsWindowGCStrategy**（GC 策略）：
- 窗口可见 → 永不释放
- 内存压力 → 立即释放
- 隐藏空闲 ≥ 1 小时 → 释放
- 释放后重建成本约 10MB

**SettingsWindowState**（可见性状态）：
- `isVisible`: 窗口是 key window（动画暂停信号）
- `isOnScreen`: 窗口真的在屏幕上（GPS/网络任务信号）
- `activeTab`: 当前 tab（动画按 tab 暂停）

**SettingsWindowVisibilityTracker**（可见性追踪器）：
- 追踪 Cmd+H 隐藏/恢复
- windowBecameKey/windowResignedKey
- windowWillClose/windowDidMiniaturize

**结论**：内存优化已经做了很多。进一步优化空间：
1. 编辑器 tab 内的子视图（Palette/Simulator/Inspector）延迟构建
2. 预览图按需生成（展开分组时才渲染）
3. undo 栈深度可配置（当前 50 级）
