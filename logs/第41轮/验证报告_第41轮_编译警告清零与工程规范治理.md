## 二、治理（修复明细，全部行为等价或恢复意图行为）

### 2.1 真实 bug 修复：WeatherBarItem 中国天气插值失效（W-1/W-2/W-3，顺带 5 处同源）

**根因**：commit 917983f7（2026-08-08「天气改用国内数据源」）新增的 `renderChinaWeather` 及同批改写的字符串把 Swift 插值 `\(` 写成了 `\\(`（源码两个反斜杠）。Swift 字符串字面量中 `\\` 是转义反斜杠，`"\\(icon)"` 实际渲染为字面文本 `\(icon)` —— 变量根本不参与插值。编译器因此报「value never used」（icon/cityLabel/located 三个局部变量在插值失效后无任何引用）。

**实证**：
- `swiftc` 最小复现：`let b = "\\(icon)"` 输出字面 `\(icon)`（非插值值）；同文件第 205 行 OpenWeather 路径 `"\\(condition_icon) ..."` 为单反斜杠、插值正常 —— 双反斜杠非作者意图。
- hexdump 取证：修复前 257 行字节 `5c5c 2869`（两个反斜杠+`(`）；修复后 `5c 28`（单反斜杠+`(`）。
- git 历史：917983f7^ 旧版该文件第 26 行 `identifier: "\\(identifier.rawValue).updatecheck"` 为单反斜杠 —— 917983f7 改写时引入双反斜杠回归。

**影响面（同源 8 处全部修复）**：
| 行号 | 修复内容 | 影响 |
|------|---------|------|
| 74 | scheduler identifier 插值恢复 | 修复前所有 WeatherBarItem 用同一字面标识符注册 NSBackgroundActivityScheduler |
| 176 | OpenWeather URL 插值恢复（lat/lon/units/appid） | 修复前请求 URL 含字面 `\(...)` 文本 |
| 239 | `\(cityName) 未知` 标题插值恢复 | 修复前显示字面文本 |
| 257/259/262/266/268 | `renderChinaWeather` 全部文本插值恢复（icon/cityLabel/湿度/风/温度/天气） | 修复前 Touch Bar 显示 `\(icon)\(cityLabel) 26°C` 字面文本 —— **真实显示 bug** |

**行为判定**：恢复作者明确意图（同文件 205 行与旧版均为单反斜杠插值）——属修复回归 bug 而非行为变更；编译器警告（W-1~3）随之消失。

### 2.2 Swift 6 前瞻：CoverCache 跨隔离边界 Sendable 盒（W-4/W-5）

`CoverCache.image(for:)` 为非隔离 async 方法返回 `NSImage?`（非 Sendable），调用方在 `Task { @MainActor }` 中 await 即跨隔离边界发送非 Sendable 结果 → Swift 6 模式下将升级为错误。**修复**：新增 `struct CoverArtwork: @unchecked Sendable { let image: NSImage? }` 作为返回盒（两处调用点解包 `.image`）。解码工作仍在协作线程池执行（方法本身保持非隔离），行为零变化；`@unchecked` 仅作装箱声明（NSImage 无 Sendable 一致性，盒内引用语义不变）。

### 2.3 deprecated API 迁移（W-6/W-7/W-8）

`onChange(of:perform:)`（macOS 14 弃用）→ 新两参数闭包 `onChange(of:) { old, new in }`。部署目标 15.0（LyricsMTMR/LyricsMTMRTests 均为 15.0），新 API 可用无需 availability 分支；旧闭包只用新值，`{ _, v in ... }` 行为完全等价。3 处（KeyBindingTabView ×2 尺寸字段、TouchBarSimulatorView ×1 scrollAnchor）。

### 2.4 deprecated API 迁移：EKAuthorizationStatus.authorized 死代码（W-9）

UpNextScrubberTouchBarItem.swift:325 `isAuthorized` 的 `#available(macOS 14.0, *)` else 分支 `status == .authorized` 在 macOS 14 弃用。**部署目标 15.0 ≥ 14.0，#available 恒真，else 分支为不可达死代码** → 直接保留 14+ 双态判定 `status == .fullAccess || status == .writeOnly`，运行行为等价（15.0 上永不落入旧分支），弃用警告消除。同文件 WidgetKit.swift:973 的 `.authorized` 在显式 `else` 分支内（编译器识别为 <14 上下文）未报警告，保持不动。

### 2.5 代码规范：作用域末 defer 恒立即执行（W-10）

RegistryReconciliationTests.swift:177 `defer { setBarHidden(false) }` 位于 if 作用域末尾（其后无语句即出作用域），编译器提示恒立即执行。**行为论证**：defer 在作用域出口执行，而该 if 块出口紧邻 `return try factory.createItem(...)` —— 直接调用与 defer 在完全相同的程序点上恢复隐藏态，行为等价；改为直接调用消除警告（注释注明缘由）。
