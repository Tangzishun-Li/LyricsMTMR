## 二、合规不动项论证（关键 4 项）

1. **selectedThemeIndex 缺键默认 0**（R47 遗留观察项第 3 条复认）：`UserDefaultsStore.integer(forKey:)` 缺键返回 0 = 第一主题。空主题列表场景（无可发现主题文件且预设无配置）下 updateTitle 显示「?」、cycleTheme 被 `guard !themes.isEmpty` 拦截、applyTheme 越界守卫返回——无崩溃无脏写。写者侧（槽位 themeN→N-1、编辑器文件名→N-1、ThemeSwitchBarItem 取模）全部经同一 ThemeSupport 约定换算，跨写者一致。**结论：既有语义成立，不动**（若未来要区分「从未选择」与「选择主题 1」，需引入可选存储迁移，登记决策候选）。

2. **无前缀键 3 处行为自洽**（R47 遗留观察项第 1 条）：postureReminderCycleStart / settings.sidebar.visible / group.expanded.* 无前缀 = 有意排除在 SettingsSync export/reset 命名空间之外（UI 布局/运行时状态不属于可分享配置）——R47 已论证，本轮零触碰。

3. **lyricsSelectionCache 随 reset 清空**（R47 遗留观察项第 2 条）：前缀命名空间既定副作用，可重建，低危，登记观察项不擅改。

4. **设置面板规则改动「下一次激活生效」**：GeneralTabView 增/改/删规则时设置窗前台 = 本应用 bundleId，updateActiveApp 规则评估天然空转；用户返回目标应用触发 didActivateApplication → 规则即时生效。与菜单路径（弹层不夺前台故立即生效）同为场景自洽，非缺陷。

4. ThemeSwitchBarItem 索引空间与槽位索引空间由「theme 文件名数字-1」约定对齐（本轮 3 用例锚定 ThemeSupport 唯一真相源）；若未来出现非 themeN 命名主题文件的槽位化需求，约定需重新审视，登记观察项。
