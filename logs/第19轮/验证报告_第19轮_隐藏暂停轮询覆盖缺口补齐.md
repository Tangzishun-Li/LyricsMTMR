## 二、方案设计（步骤②）

### 2.1 共享封装（新文件 `LyricsMTMR/MTMR/Widgets/TBPausableTimer.swift`，零拷贝）

- `TBPauseGate`：NSLock 保护的布尔标志 + 变更检测（`setPaused` 返回是否真正变化，重复调用幂等）；供 CPUBarItem 等非 Timer 自循环复用。
- `TBPausableTimer`：主 runloop 重复 Timer 的可暂停封装。
  - **暂停 = 无效化底层 Timer**：不 fire、不占 runloop 唤醒、handler 零调用（比「定时器继续走但回调早退」更彻底，兑现「隐藏期间零空转」）；
  - 恢复 = 以**原 interval/tolerance** 重建 Timer（同参 `Timer.scheduledTimer`，与改动前同构），`immediateFireOnResume` 为 true 时立即补发一次 handler（数据型 widget 避免陈旧显示，如 StockBarItem）；
  - `reschedule(interval:)`：改频率并重建（StockBarItem 交易时段边界 10s↔60s 即时切换，语义与原 `rescheduleRefreshTimer` 相同）；暂停期间只记新 interval，恢复时按新值生效；
  - `start()`/`stop()`：浮层级 Timer 生命周期（OpenCodeGo 浮层计时、TimestampConvert 浮层 tick），start 幂等重建（与原 invalidate+recreate 模式一致）；
  - 线程安全：所有 Timer 操作 hop 到主线程（runloop Timer 必须在主线程），每个 hop 复查当前标志丢弃过期操作（快速 pause/resume 竞态安全）；标志读写全走 NSLock；deinit 捕获 orphan Timer 到主线程 invalidate（runloop 强持有已调度 Timer，防泄漏）。
  - 新建即未暂停（gate 默认 false，start() 立即安装），满足「新建 item 默认未暂停」。

### 2.2 8 item 接入（全部 conform `TBPollPausable`，controller 零改动）

| item | setPaused 实现要点 |
|------|--------------------|
| StockBarItem | 行情 + 跑马灯两个 wrapper 同时暂停；恢复时行情立即刷新（fetch 后 `refreshData` 完成回调带 `!isPaused` 守卫：隐藏期间到达的响应不落库不启跑马灯，恢复后重新拉取）；交易边界检查移入 `refreshBoundaryCheck()`（原逻辑等价） |
| CPUBarItem | `TBPauseGate` + `refreshAndSchedule()` 开头 `guard !pauseGate.isPaused`：暂停后已触发的 hop 直接返回且不再调度下一 hop（链终结）；恢复时 `refreshAndSchedule()` 立即采样一次再按原间隔继续；单在途性质由链本身保证（每次调用恰好调度一个后继），无双重调度面 |
| DnDBarItem | 1s wrapper（tolerance 0.1 原值），恢复立即 `refresh()` 图标 |

### 2.3 设计要点对照需求

1. 隐藏（dismissTouchBar/黑名单/exitTouchbar）→ controller 广播 `setPaused(true)` → 各 item Timer 无效化/链终结；显示（presentTouchBar）→ 广播 `setPaused(false)` → 按原节奏恢复，数据型 item 立即刷新一次 ✓
2. 未隐藏时严格等价：同参重建 Timer（interval/tolerance/首刷时机不变）；CPUBarItem 链节奏不变 ✓
3. 新建默认未暂停（gate 默认 false）✓
4. 线程安全：NSLock 标志 + 单在途（Timer 天然单实例；CPU 链单后继）+ 主线程 hop + 过期操作复查 ✓
5. 单测 9 用例（见第五节）✓
6. 零拷贝（8 item 共用 2 个共享类型，无逐 item 复制）；未新增日期表等 ✓

## 四、等价性论证

1. **新建默认未暂停**：`TBPauseGate` 默认 false；`start()` 立即安装 Timer；CPUBarItem 初始化即 `refreshAndSchedule()` 首采。与改动前行为一致。
2. **interval / tolerance / 首刷时机不变**：wrapper 以同参 `Timer.scheduledTimer(withTimeInterval:repeats:block:)` 安装，tolerance 仅在有原值处透传（Stock/跑马灯原无 tolerance 则保持 nil）；`start()` 与原 `scheduleRefresh`/`scheduleRefreshTimer` 一样 hop 主线程后安装，首 fire 时机 = interval；CPUBarItem 首采仍为 init 立即执行，后继 hop 间隔不变。
3. **StockBarItem 交易时段边界即时切换**：原逻辑在每次 tick 检查 `timer?.timeInterval != effectiveRefreshInterval` 则重建；新实现 handler 内 `refreshBoundaryCheck()` 检查 `currentInterval` 并 `reschedule`，语义一致（含隐藏期间：暂停只记新 interval，恢复时按新值安装，等效于恢复后首 tick 即校正）。
4. **浮层/跑马灯生命周期**：startMarquee 每次数据到达重建（与原 invalidate+recreate 相同）；OpenCodeGo 浮层 start/stop 与原 Timer 建/销一致；TimestampConvert buildOverlay 每次重建前先 stop 旧 wrapper（与原 `timer?.invalidate()` 相同）。
5. **deinit 语义**：wrapper deinit 在主线程 invalidate orphan Timer（runloop 强持有已调度 Timer，必须显式 invalidate 防泄漏）；各 item 原 deinit 的 `timer?.invalidate()` 由 wrapper 承接；CPUBarItem 链上 block 均 `[weak self]`，item 释放后 hop 自动失效（deinit 单测实证「不复活」）。
6. **未隐藏路径零差异**：广播只在 dismiss/present 时触发；未隐藏时 `setPaused` 未被调用（或重复调用幂等无副作用），Timer 行为与改动前逐位等价。
7. **竞态**：pause/resume 与 Timer fire 均串行在主线程（hop FIFO + 标志复查），任意序列的最终状态 = 最后一次标志变化决定（安装→无效化 或 无效化→安装 均正确收束）；CPU 链单在途由「每次调用恰好调度一个后继」保证，暂停断链后恢复恰好重新拉起一次。

## 七、风险点

1. **CPUBarItem 潜伏崩溃已修复但未真机验证**：`deinit` 的 `refreshQueue?.suspend()` 是 libdispatch 明确禁止的操作（pending suspension count 下释放队列即 EXC_BREAKPOINT）；因 actions 强自引用环生产环境从未触发 deinit，本轮修复无线上行为差异，但建议后续轮次顺手处理 actions 环（本卡不动，超出范围）。
2. **真机冒烟仍缺失**：黑名单隐藏/恢复、恢复立即刷新的实际观感（尤其 StockBarItem 恢复后首帧）依赖 Touch Bar 真机，逻辑已由 9 单测覆盖，渲染观感留待用户验证（延续第 8/17/18 轮同类遗留口径）。
3. **DarkModeBarItem（System，3s Timer）等未列入本卡范围**：grep 全景发现 Media/Productivity 类 widget（MusicBarItem、PlaybackProgressBarItem、AudioSpectrumBarItem、ReadTimer、BreathingGuide、StandupTimer、ClipboardHistory、DarkModeBarItem、BrightnessViewController）也带 Timer，但按父卡范围约定本卡只覆盖任务清单 8 项；其中播放器类 Timer 与播放状态耦合、DarkMode 3s 轮询属低成本读取，是否纳入后续「隐藏零空转」统一治理留待父任务决策（已登记遗留跟踪）。
4. **浮层协同边界**：OpenCodeGo 浮层若在 bar 隐藏期间保持 isPopupVisible（用户浮层打开时切到黑名单 app），恢复时浮层计时器按原样重启；系统模态已被 control strip 替换，浮层视图重建由 controller 的 reloadPreset 路径负责，与本卡无关（行为与改动前一致）。
5. **文档同步**：iteration-log.md 追加「第 19 轮 / 子任务 A」记录；file-structure.zh.md 登记本报告行与新文件。
