## 二、决策依据

### 2.1 用户主动激活类（Pomodoro/ReadTimer/StandupTimer/BreathingGuide）：不纳入

任务要求明确「隐藏期间用户看不到 item，计时是否继续是产品决策，请给出建议并实现时遵守」。建议与实现一致：**计时继续，不纳入暂停**。依据：

1. **语义承诺与可见性无关**：番茄钟的交付物是「到点提醒」（UNUserNotification 通知）——用户开启番茄钟后切到黑名单 app（全屏 IDE/视频）埋头工作，恰恰是最需要到点提醒的场景；暂停会推迟甚至吞掉通知，破坏核心承诺。站会倒计时同理：倒计时必须走到 0 才触发提醒/闪烁。
2. **用户激活 = 用户在场**：这些定时器全部由用户在浮层内显式开启，且全部是「浮层作用域」（ReadTimer/StandupTimer/BreathingGuide 的 Timer 在 `buildOverlay` 创建、`closeOverlay` 销毁；Pomodoro 由点击启动、重置/完成销毁）。浮层是系统模态展示——用户正在看它，不存在「运行中但看不见」的状态（切到黑名单 app 时浮层随 bar 最小化属极端边界，此时暂停动画/倒计时反而让用户回来后看到被冻结的会话）。
3. **成本可忽略**：这些 tick 全部是本地计数/动画（无网络、无 IPC、无文件 IO、无系统 API），1s/0.5s/0.05s 一次内存操作的成本与「轮询类」的私有 API/网络/IO 空转不在一个量级；「零空转」治理的目标是轮询工作（第 18/19 轮统一口径），不是用户会话。
4. **对称性**：若暂停，ReadTimer 少计阅读时长、Standup 倒计时停摆、呼吸动画冻结——全部是用户可感知的回归；而「不纳入」的代价是隐藏期间每秒一次计数器递增（不可感知）。

### 2.2 持续轮询类：纳入 + 两个产品取舍

- **ClipboardHistory 隐藏期丢中间条目**：纳入后隐藏期间新增复制只丢「中间条目」，恢复时 `changeCount` 已变化，`immediateFireOnResume` 的首次 tick 立即收录最新一条。取舍依据：item 不可见时浮层不可达（无消费者），且历史为进程级静态数组+磁盘持久化，已收内容零损失；相比每 1s 轮询剪贴板 24/7（用户可能永远不打开浮层），隐藏暂停是净收益。若用户在意隐藏期复制，可后续改为事件驱动（`NSPasteboard.observe`）替代轮询——超出本卡范围登记遗留。
- **恢复立即补刷（immediateFireOnResume=true）**：DarkMode/NightShift/Time/Brightness/PlaybackProgress/AudioSpectrum/Music 链全部采用——隐藏期外部状态可能变化（深色模式切换、时间流逝、播放进度前进），显示瞬间立即刷新避免陈旧显示（第 19 轮 Stock 同款语义）。

### 2.3 播放器类：Timer 纳入、事件流不动

PlaybackProgressBarItem 的 `$trackInfo` Combine sink 与 AudioSpectrumBarItem 的音频 tap 均为事件驱动（有事件才跑），不属于轮询空转，保持不动；仅其上的周期轮询 Timer 纳入暂停。

## 五、等价性论证

1. **新建默认未暂停**：gate 默认 false，`start()` 立即安装；8 item init 均同步调用首刷（DarkMode/NightShift/Time/Brightness 首 `refresh()`/`updateTime()` 不变；Music 链 init 即起；PlaybackProgress 的 sink 立即收到当前 trackInfo；AudioSpectrum init 即 `startCapture()+startDisplayTimer()`）。
2. **interval / tolerance / runloop mode / 首刷时机不变**：wrapper 同参重建；`.common` 仅 Brightness/ClipboardHistory 透传（原实现即 `.common`）；DarkMode 3s 为生产默认值，init 签名默认参数保证 BarItemFactory 调用 `DarkModeBarItem(identifier:)` 零改动。
3. **MusicBarItem 跑马灯安装时机不变**：仍仅在 `updatePlayer` 出现非空歌名时安装（`marqueeStarted` 守卫保证 setPaused 不触碰未安装的 wrapper）；换歌时 `start()` 重建语义 = 原 `invalidate()+recreate`；无歌名时跑马灯不存在（与改动前一致——不产生凭空 timer）。
4. **AudioSpectrumBarItem handler 逐行等价**：`spectrumTick()` 与原闭包逐行一致（lastRealFeed/lastAudibleMic 宽限、播放态合成、非播放态衰减）；仅外层 Timer 换 wrapper。
5. **deinit 语义**：wrapper deinit 主线程 invalidate orphan Timer；各 item 原 `timer?.invalidate()` 由 wrapper 承接；Music 链 block 均 weak self（链 hop 的 asyncAfter `[weak self]`），item 释放后 hop 自动失效。
6. **未隐藏路径零差异**：广播只在 dismiss/present 触发；未隐藏时 `setPaused` 幂等无副作用。
7. **竞态**：pause/resume 与 Timer fire 串行主线程（hop FIFO + 标志复查）；Music 链单在途由「每次调用恰好调度一个后继」保证（同 CPUBarItem 论证）。

## 八、风险点

1. **AudioSpectrumBarItem 采集 tap 未纳入暂停**：SCK system tap / AVAudioEngine mic engine 为事件驱动回调（非 Timer），隐藏期间仍随音频硬件持续回调（FFT 已在 0.04s displayTimer 与 tap 之间做了节流，tap 内仅 accumulate + 按需 FFT）。暂停需 stopSystem/stopMic + 恢复时重启引擎——SCK 重启有权限弹窗与状态机风险（macOS 13+ 每次 `SCShareableContent` 重取都要 Screen Recording 授权），本卡范围外登记遗留；displayTimer（25fps 主频空转）已纳入，空转大头已消除。
2. **真机冒烟仍缺失**：黑名单隐藏/恢复的实际观感（时钟补刷、跑马灯恢复、光柱恢复首帧、剪贴板恢复收录）依赖 Touch Bar 真机，逻辑已由 6 单测覆盖，渲染观感留待用户验证（延续第 8/17/18/19 轮同类遗留口径）。
3. **ClipboardHistory 隐藏期丢中间条目**：纳入的设计取舍（见 2.2 节）——若用户在意可改事件驱动（`NSPasteboard.observe`）替代 1s 轮询，登记遗留。
4. **DarkModeBarItem init 签名扩展**：新增默认参数不改生产调用面；`Widget` 协议静态属性与 factory 调用均未动。
5. **文档同步**：iteration-log.md 追加「第 20 轮 / 子任务 A」记录；file-structure.zh.md 登记本报告行。
