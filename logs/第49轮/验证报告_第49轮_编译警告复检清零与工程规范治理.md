## 二、治理（修复明细，行为等价）

### 2.1 真实问题根因修复：非可选 String 上的死代码 ?? 兜底（W-49-1）

**根因**：`TBMetricView.value` 为非可选 `String`（WidgetKit.swift:121 `var value: String = ""`）。第 45 轮新增 `testWeatherOutfitFetchFailureShowsFailureState` 时，将主值断言 `(item.metric.value ?? "").contains("°")` 与副值断言 `(item.metric.subValue ?? "").contains("°")` 同型书写，但二者类型不同——`value` 非可选（`?? ""` 右侧恒不可达，死代码），`subValue` 可选（`?? ""` 为有效兜底）。编译器对 :324 发出「right side is never used」警告，:326 无警告。

**修复**：`:324` `XCTAssertFalse((item.metric.value ?? "").contains("°"))` → `XCTAssertFalse(item.metric.value.contains("°"))`。非可选 `String ?? ""` 求值恒等于原值，行为完全等价；断言未放宽（仍要求失败态主值不得包含温度读数「°」）。

**影响面检查（全仓 `?? ""` 扫描）**：grep 全仓 `?? ""` 共 100+ 处，除本处外左侧均为真可选类型（`as? String` / `string(forKey:)` / `.first` / `.stringValue` / 字典下标等），无一死代码——编译全量 0 警告亦为佐证（Swift 编译器对可证明非可选的 `??` 均会报警，本次全量编译仅此 1 条）。
