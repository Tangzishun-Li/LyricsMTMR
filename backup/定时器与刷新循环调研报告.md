## 一、用户激活配置中实际在跑的定时器

用户配置树（5 group 展开后共 40+ 子项）中，真正带定时器的只有 4 处：

| 位置 | 定时器 | 状态 |
|---|---|---|
| `lyrics`（karaoke 模式） | playbackTimer 0.25s + marquee 60fps + KaraokeLabel 30fps | 播放中运行（见 §二） |
| `group 💻 → appleScriptTitledButton` | `refreshInterval: 5` 递归 asyncAfter | **每 5s fork 一次 `top -l 2` 命令** |
| `stock` ×2（compact，symbols 为空） | 10s Timer | 每 10s 触发一次空操作（无网络） |
| `pomodoro` | DispatchSourceTimer 1s | 仅用户点击"开始"后运行 |

其余全部无定时器：battery / weather / upnext / volume 滑条（VolumeViewController 无 Timer）/ dock / staticButton×11 / themeSwitch / exitTouchbar / brightness 按钮。**Time/DnD/NightShift/DarkMode 等 1s 系统项均不在激活配置中**。

## 二、重点项评估（文件:行号 证据）

**1. LyricsEngine.playbackTimer 0.25s — 设计良好，不泄漏**
- `LyricsEngine.swift:711` 创建；回调 `LyricsEngine.swift:712-726`：guard `playing` + `timeBase`，重建 `EngineTrackInfo` + `updateKaraokeProgress()`（轻量 map）。
- 启停由 `trackInfo` 的 `didSet` 驱动：`LyricsEngine.swift:440` `syncPlaybackTimer(with:)` → 暂停/停止即 `stopPlaybackTimer()`（`729-732`）；deinit 也停（`488`）。**非常驻、事件同步、无泄漏**。
- 但它是 Combine 链的节拍器：每 0.25s 的 `trackInfo` 变更会经 `LyricsTouchBarItem.swift:154-181` 的 6 层 combineLatest 触发 `onLyricsUpdate` → `handleTextScroll`（见下）。

**2. LyricsTouchBarItem marqueeTimer 60fps — 最大隐患 + 两个缺陷**
- `LyricsTouchBarItem.swift:371`，`MarqueeMetrics.fps = 60.0`（`:25`）。
- 启动条件（`handleTextScroll` `:291-323`）：`marqueeEnabled` 默认 true（`LyricsItemConfig.swift:51`）、`marqueeStyle` 默认 `.marquee`（`:52`）、文本溢出 clipWidth、**且当前行无 timetags**。普通 LRC 行无逐字时间标签 → **用户日常播放时此 60fps Timer 几乎常驻**。
- **缺陷 A（暂停不停）**：`onLyricsUpdate` 的暂停分支（`LyricsTouchBarItem.swift:279-285`）只调用 `lyricsLabel.pauseProgressAnimation()`，**不调用 stopMarqueeTimer** → 暂停播放时 60fps 继续空转。
- **缺陷 B（0.25s 重启/滚动回跳）**：每 0.25s 的 playbackTimer tick 都会经 Combine 链重新进入 `handleTextScroll` → 无 timetags 行走 `startMarquee`（`:316-321`）→ `stopMarqueeTimer()` + 重建 timer + **`marqueeStartTime = Date()` 重置**（`:369`）→ 滚动位置每 0.25s 跳回 0（`marqueeTimer` 回调 `:371-380` 从 `elapsed=0` 重新算 offset）。视觉上文本反复回跳，同时每 0.25s 做一次 timer invalidate+重建。
- 停止路径正确：行切换有 timetags → `stopMarqueeTimer`（`:307/317`）；`resetScrollPosition`（`:383-386`）；`deinit`（`:75-77`）。**无泄漏**（weak self + deinit 清理齐全）。

**3. KaraokeLabel karaokeTimer 30fps — 干净但常驻**
- `KaraokeLabel.swift:355`（`Timer(timeInterval: 1/30)`，加到 `RunLoop.main .common` `:368`）。仅在 `setProgressAnimation`（有 timetags 行）时启动（`:279`）；暂停 `stopKaraokeTimer`（`:287`）、移除动画停止（`:300`）、播完自动退休（`:363-366`）、pause/resume 对称。回调只做 `needsDisplay = true`（`:361`）→ `draw()` 里 `CTFrameDraw` 裁剪扫光（`:340-351`）→ **30fps 全帧重绘**。不泄漏。

**4. TouchBarMirrorWindowController syncTimer 0.1s — 默认关闭，开启则最重**
- `TouchBarMirrorWindowController.swift:89`；回调 `syncFromTouchBar()`（`:103-132`）**每 0.1s 全量清空 stackView 并为全部 item 重建 NSView**（`makeItemView` 创建 NSButton 等）。仅 `show()` 启动（`:26/73`），`hide()` invalidate（`:77-78`）。默认 **false**（`AppSettings.swift:153` `defaultValue: false`）→ 用户当前不跑。若开启是 10Hz 全量视图重建，代价最高。

**5. AudioSpectrumBarItem 0.04s（25fps）— 不在激活配置**
- `AudioSpectrumBarItem.swift:565`；init 即 `startCapture() + startDisplayTimer()`（`:283-284`）。回调：真实音频 feed 近 0.25s 内直接 return（`:570-573`），否则合成频谱 25fps `smooth` → `spectrumView.levels` 重绘；非播放时也持续平滑到 0.02（`:578-581`）→ **item 存在即常驻 25fps 重绘**。deinit 全清理（`:299-310`）。系统 tap 是事件驱动音频回调（`:325+`）。不泄漏，但用户若添加该 item 会持续消耗。

**6. StockBarItem 10s — 网络+重绘；当前 symbols 为空 → 无网络**
- `StockBarItem.swift:78`（init 即 `scheduleRefresh` `:61-62`），间隔 `max(配置,5)`（`:40`）→ 用户 10s。回调 `refreshData()`（`:86-114`）：每只股票 1 个 URLSession 请求（腾讯/东财分钟线 API `:128-138`）+ `updateDisplay` → `renderStock` 整图 `NSImage` 重绘（`:400+`）。marqueeTimer 3s（`:362`）仅 `displayMode=="marquee"`（`:51/109-110`）→ **用户 compact 模式不跑**。deinit 双 invalidate（`:67-70`）。当前配置 symbols 为空 → `refreshData` 直接 return（`:87-91`），**实际无网络请求**；一旦配置股票，每 10s ×N 请求 + 全量重绘。

**7. OpenCodeGoUsageBarItem — 不在激活配置，且自身干净**
- init refreshTimer ≥60s（`:446/462`）；popup 期 tickTimer 1s + popupRefreshTimer（`:755-759`），`closePopup`→`stopPopupTimers`（`:765-770`），deinit 全 invalidate（`:470-474`）。无泄漏。

**8. 脚本按钮 5s（用户配置实际在跑）**
- `AppleScriptTouchBarItem.swift:49`：递归 `asyncAfter(interval)` 每 5s 在串行队列 `execute()` 一次 **`top -l 2 -n 0 -F | egrep ... | awk`**（配置 inline source）。`top -l 2` 做两次系统采样，每次 fork 3 个子进程，瞬时 CPU/IO 峰值每 5s 一次。weak self 递归 → item 释放后自然终止，无泄漏。**5s 间隔过密，是用户配置里除歌词外最活跃的轮询**。

**9. 其余（均不在激活配置，机制均正确）**：`TimeTouchBarItem.swift:16`（1s 改标题字符串）、`DnDBarItem.swift:21`（1s 读 CFPreferences）、`NightShiftBarItem.swift:36`（1s XPC CBBlueLightClient）、`DarkModeBarItem.swift:16`（3s UserDefaults）、`BrightnessViewController.swift:26`（滑条轮询）、`PlaybackProgressBarItem.swift:208`（0.5s 滑条，`tolerance 0.05`）、`MusicBarItem.swift:292`（0.25s marquee，仅检测到歌名时启动，4Hz 改标题）、`UsageBarItem.swift:88`/`DeepseekBalanceBarItem.swift:32`（≥60s）、`PomodoroBarItem.swift:85-88`（1s，仅计时中）、`StandupTimer.swift:61`/`BreathingGuide.swift:113`/`ReadTimer.swift:56`/`ExpenseTracker.swift:49`/`TimestampConvert.swift:28`（popover 内计时，关闭即 invalidate）、`CustomButtonTouchBarItem.swift:292`（长按 0.4s 一次性，触摸事件驱动，`touchesEnded/Moved/Cancelled` 全 invalidate `:298-318`）。

**10. 设置窗口 TimelineView（15% CPU 的源头，已带暂停但存在盲区）**
- `LyricsTabView.swift:1057` 30fps karaoke 预览 + `UnifiedSettingsWindowController.swift:852` 0.09s（≈11fps）均衡器，均带 `paused:` 参数：窗口不可见或非 lyrics tab 即暂停（`:1058`、`:1113`）。`SettingsWindowState.isVisible` 仅在 `windowWillClose` / `didBecomeKey` / `didMiniaturize` / `didDeminiaturize` 更新（`:135/162/166/170`）。**盲区**：窗口若经 `orderOut`/切 Space/非标准方式隐藏，`isVisible` 不复位 → 离屏 DisplayLink 继续跑（与观察到的 15% 吻合）。此外 `SettingsTabCache`（`:886-892`）缓存已访问 tab 的视图，窗口重新打开即恢复动画。

## 三、泄漏检查结论

| 定时器 | 移除/停用后是否清理 | 判定 |
|---|---|---|
| playbackTimer | `didSet` 自动停（`:440`）+ deinit（`:488`） | ✅ |
| marqueeTimer | deinit（`:75-77`）+ 行切换停；**暂停播放不停** | ⚠️ 暂停时空转 |
| KaraokeLabel 30fps | pause/remove/播完自动停（`:287/300/363`） | ✅ |
| Stock/Usage/Deepseek/系统项 | 均 deinit invalidate；隐藏 item 根本不创建（`TouchBarController.swift:659-669`） | ✅ |
| TouchBarController 移除 | `discardCurrentItems` → `BarItemDiscarding`（`:677-680`）+ items 字典整体替换 → 旧 item deinit | ✅ 通用机制成立 |
| 脚本按钮 / TBPollItem | weak self 递归，释放即停（`AppleScriptTouchBarItem.swift:49`、`WidgetKit.swift:574-599`） | ✅ |
| Mirror syncTimer | hide() invalidate（`:77-78`） | ✅ |

**唯一实际问题**：marqueeTimer 在暂停播放时不停。

## 四、MediaRemote 与 NetEase

- **run.pl + MediaRemoteMRBridge.dylib（MediaRemoteAdapter.swift:34-84）**：perl 子进程加载 dylib 后调 `loop()` → **C 侧 `CFRunLoopRun()`（MediaRemoteMRBridge.m:342-373），纯事件驱动**——空闲 0% CPU，仅 MediaRemote 通知到达时输出一行 JSON（stdout → `readabilityHandler` 解析 `:54-67`）。无轮询。stopListening/deinit 正确 terminate（`:86-89`、`:185-187`；LyricsEngine deinit `:488-489`）。开销可忽略。one-shot 控制命令（play/seek 等）每次 fork perl 进程，仅在用户点击时发生。
- **NetEaseProvider**：全仓无 Timer/retry 轮询，纯请求-响应（一次搜索 1 个 HTTP 请求）；歌词缓存命中则零网络（`LyricsEngine.swift:892-916`）。无轮询。

## 五、日常场景 CPU 放大排序与优化建议

**放大排序（按用户实际配置）**：
1. **歌词 marquee 60fps 常驻**（普通 LRC 播放中）+ 暂停不停 + 每 0.25s 重建回跳 —— 日常最大定时器开销，且带视觉 bug；
2. **appleScriptTitledButton 5s fork `top -l 2`** —— 每 5s 一次进程簇峰值；
3. 设置窗口离屏 DisplayLink（若窗口非标准隐藏则持续 15%）；
4. 股票 10s 轮询（当前未配 symbols 无网络，配置后即放大）；
5. 各 popover 计时器（仅打开时，可忽略）。

**优化建议（按优先级）**：
1. **marqueeTimer（`LyricsTouchBarItem.swift:371`）**：① 暂停时 `stopMarqueeTimer()`（补进 `:279-285` 暂停分支）；② 修复 0.25s 重启回跳——`startMarquee` 前检查 `marqueeTimer != nil && marqueeStartTime != nil` 则直接复用，仅 `lineChanged` 时重建；③ fps 60→30（触摸条肉眼无差）；④ 改用 `CADisplayLink` 与屏幕刷新同步（省 runloop 唤醒）。
2. **playbackTimer（`LyricsEngine.swift:711`）**：0.25s 可保留（行切换已由独立的 `scheduleLineCheck` asyncAfter 事件驱动 `:1066-1096`），但建议把 `handleTextScroll` 移出 0.25s Combine 链——仅在 lineChanged/状态变化时调用，彻底消除 60fps timer 重建源。
3. **脚本按钮**：`refreshInterval` 5s → 建议 ≥15s，或改用后台队列的 `TBPollItem`（`WidgetKit.swift:546-607`）避免主线程同步 fork。
4. **StockBarItem（`StockBarItem.swift:78`）**：配置股票时下限 10s→30s（分钟线数据 1 分钟才变），并仅在 `isMarketOpen()`（`:347-356`）期间轮询。
5. **设置窗口（`UnifiedSettingsWindowController.swift:17-25`）**：`isVisible` 改为监听 `NSWindow.willMoveToWindow/NSWindow.didOrderOut` 等全量可见性通知，保证任何隐藏路径都复位 → 根治离屏 DisplayLink 15%。
6. **MirrorWindow（默认关）**：若开启，把 0.1s 全量重建（`:103-132`）改为增量 diff 或 TouchBarController 变更事件驱动。

**结论**：观察到的"定时器当前不是主因、SwiftUI DisplayLink 占 15%"与代码一致——当前配置下定时器总量小（歌词 60fps 是唯一高频项，且只在播放时跑；其余为 10s/5s 低频）。但歌词 marquee 存在"暂停不停 + 0.25s 重启回跳"两个缺陷，是日常使用中唯一会持续放大 CPU 的定时器，建议优先修复；离屏 DisplayLink 的根治点在 `isVisible` 的状态维护盲区。
