## 三、逐项归因：为什么占内存、触发条件、占比

### A. CoreAnimation 136MB —— 幽灵设置窗口的图层树（占比最大单项，44.7%）

**触发条件**：打开过一次设置窗口（哪怕只开 1 秒再关闭）→ 永久生效，直到 app 退出。

**为什么占**：三条代码路径叠加，把一棵"夜店风"SwiftUI 视图树完整钉在内存里：

1. **关窗不释放（根）**
   - `App/AppDelegate.swift:143` `private var unifiedSettingsController: UnifiedSettingsWindowController?` 强持有，`:156-167` openSettings 仅 nil 时创建，**全文件无置 nil 路径** → 窗口对象、NSHostingView、整棵 SwiftUI 树永不 deinit。
   - `Preferences/UnifiedSettingsWindowController.swift:133-137` windowWillClose 只清 `weak static current`（:95）+ isVisible 标志 + Dock 清理，**清不掉 AppDelegate 的强引用**。
   - 实锤：heap 里 `NSHostingView<SettingsRootView>`（2KB 对象 + displayLink 48B + PointerRegionState 字典 64KB）**存活**；窗口列表 onscreen=false、alpha=1.0（详见性能总报告 §一）。

2. **21 个 tab 全量挂载 + 全量缓存**
   - `:1119-1127` `ZStack { ForEach(SettingsTab.allCases) { tabContainer(for: tab) } }` —— **所有 21 个 tab 视图树同时挂载**，仅用 opacity 切换，从不卸载。
   - `:886-892` `SettingsTabCache`（`[SettingsTab: AnyView]` 字典）把**每个访问过的 tab 的 AnyView 永久强持有**（只在 :937 配置导入时 removeAll）→ 每个 tab 的视图图/图层树各留一份。

3. **永不停止的动画 + 每帧重渲的模糊**
   - `:437-441` `Deck.Background` 的 `repeatForever` 动画（全项目唯一）驱动两个 700×700 / 620×620 RadialGradient 持续漂移；`:421-436` 两者带 `.blur(radius: 5)`，blur 内容每帧变化无法缓存 → 源+目标双 backing ≈ 24~30MB 常驻。
   - 19 处 `.shadow(`（Card :472 / Pill :548 / NavItem :1212 等）——每处一个离屏 shadow 层。
   - 实测印证：1030 个 CA regions；主线程大量 CAAnimation dealloc 抖动。

**估算占比**：CoreAnimation 136MB ≈ **总内存的 45%**；若含其钉住的视图图（C/F/L 大头），整棵幽灵树 ≈ **250MB+（80%+）**。

**低风险修复**（均已在性能总报告路线图中）：
1. `AppDelegate.swift:143` 改 `weak var`，或 windowWillClose 回调置 nil → 整棵树释放，136MB CA + 大部分 B/C/E/F/L 回收。**最大单项，行为无感。**
2. `Deck.Background` 加 `paused: !windowState.isVisible`（复用 :1113 Equalizer 已有模式）→ 停止 60fps 离屏渲染。
3. 去掉两处 `.blur(radius: 5)` 改静态纹理（省 24~30MB backing）。
4. `SettingsTabCache` 加 LRU（保留最近 3~5 tab）。

---

### B. MALLOC non-object 42MB —— 最大的"无名"缓冲（13.8%）

**为什么占**：heap 里 173,426 个无类型原始 malloc 节点。这类缓冲包括：NSAttributedString 底层存储、CoreText 字形缓冲、NSImage/CGImage 像素数据、SwiftUI DisplayList 序列化缓冲、字符串数据。**大部分被幽灵设置窗口的 21 tab 视图树（大量文本/图标/图形）钉住**；小头是歌词渲染路径（KaraokeLabel）的 CT 缓冲。

**触发条件**：同 A——开过设置窗口即常驻；歌词路径仅在播放时抖动。

**估算占比**：42MB（13.8%），其中窗口相关大头约 60-70%（25-30MB）。

**低风险修复**：无需单独处理——随 A 的窗口释放自动回收；歌词路径优化（下 §）可减抖动峰值。

---

### C. SwiftUI 视图图 20MB —— 三棵视图树的依赖数据（6.7%）

**为什么占**：heap 显示 **36,196 个 `TypedElement<ReusableInputs>` + 13,914 HelpStyle + 12,892 SourceInput + 7,180 StyleableView + 7,111 PrimitiveButtonStyle + … 共约 11.5 万个 SwiftUI 视图图节点（每节点 80~96B）**，加 4,536 个 `AnyTrackedValue` 字典桶（3.2MB）、1,384 个 LayoutEngineBox、DisplayList.Item 7,613 个（1.4MB）。三棵常驻 SwiftUI 树：设置窗口 21 tab（最大）、popover、Touch Bar 歌词/系统项。

**触发条件**：设置窗口访问过的 tab 越多越大（SettingsTabCache 全量缓存）；popover/Touch Bar 常驻。

**估算占比**：~20MB（6.7%），其中设置窗口占 ~70-80%。

**低风险修复**：随 A 释放；`SettingsTabCache` LRU 后仅保留活跃 tab。

---

### D. CoreSVG / SF Symbols 7MB —— 图标矢量缓存（2.3%）

**为什么占**：heap 显示 **21,721 个 SVGAttribute（2.4MB）+ 18,369 SVGPathCommand（1.2MB）+ 5,315 SVGAttributeMap + 1,587 SVGPaint + 1,066 SVGShapeNode + 529 套 SVGDocument/SVGRootNode + 751 CUIVectorGlyphLayer + 531 _CUIThemeSVGRendition**——约 **529 个 SF Symbol 的完整 SVG 矢量数据**常驻进程。来源：设置窗口数百个 `NSImage(systemSymbolName:)` 按钮图标（Editor 调色板/导航/装饰）+ Touch Bar items + popover。CoreSVG 对同一符号只缓存一份，**换图标/重建 item 不会翻倍**，但被窗口钉住永不释放。

**触发条件**：设置窗口打开一次即全量缓存；Touch Bar 图标常驻。

**估算占比**：7.1MB（2.3%），窗口占大头。

**低风险修复**：随 A 释放大部分；此项本身有界（每符号一份），非紧急。

---

### E. AutoLayout 4MB —— 4.5 万个约束对象（1.3%）

**为什么占**：11,864 NSAutoresizingMaskLayoutConstraint + 11,460 NSISVariableObservation + 11,383 NSISRestrictedToZeroMarkerVariable + 6,033 NSLayoutDimension + 5,746×2 NSIS 变量 + 3,100 _NSViewLayoutAux + 6,002 anchors + 721 NSLayoutConstraint。这是 AppKit 视图（设置窗口 NSHostingView 内部桥接 + Touch Bar items + popover）的布局体系，每 view 挂多个约束/变量。

**触发条件**：常驻（Touch Bar 本体）+ 开设置窗口后放大。

**估算占比**：3.9MB（1.3%），窗口相关约一半。

**低风险修复**：随 A 释放；无需单独处理。

---

### F. AttributeGraph 2.8MB —— 2,510 个 AGSubgraph（0.9%）

**为什么占**：9,212 个 AttributeGraph Data（2.3MB）+ 2,510 AGSubgraph + 1,871 _SetStorage<AGAttribute>。SwiftUI 依赖图：每视图子树一个 subgraph，21 tab + popover + Touch Bar items = 2,510 个。

**触发条件**：同 C。

**低风险修复**：随 A 释放。

---

### G. Foundation/CF 6MB —— 字符串与集合（2.0%）

13,492 CFString + 2,275 CFData + 6,101 NSMutableArray + 5,835 NSMutableDictionary + 各集合 storage。全局配置字符串、歌词文本、视图树文本。随 A 释放大半；**无无限增长集合**（见 §四 排除清单）。

---

### H. Swift 元数据 7.7MB —— 进程级一次性开销（2.5%，不可优化）

Swift Metadata 4.2MB（2,379 个 Swift 类的类型信息，任何 Swift app 都有）+ Class.methodCache 1.6MB + Closure context 1.6MB。**这是正常开销，不是泄漏**——排除在优化目标外。

---

### I. CoreText 1.9MB + J. CoreGraphics 1.9MB —— 文字与图形对象

- CoreText：969 CTRun + 712 CTLine + 713 _CTNativeGlyphStorage + 680 _NSCoreTypesetterLayoutCache —— 歌词渲染（KaraokeLabel）+ 界面文本。
- CoreGraphics：3,383 CGPath（形状/阴影路径）+ 887 CGImage + 749 CGDataProvider + 982 CGColor。

**触发条件**：播放歌词时（KaraokeLabel）+ 设置窗口图形。
**估算占比**：合计 3.8MB（1.2%），占比小但**是每帧抖动源**（见 §五）。

---

### L. untagged VM 17MB（5.6%）

VM_ALLOCATE 匿名区：字符串存储页、CT/GD 缓冲页、视图背衬页。大头被幽灵窗口树持有。

## 五、内存"抖动源"（不占常驻，但推高 MALLOC 区水位与 CPU）

以下路径每 tick 新建/释放对象，**不累积**（footprint 平台期可证），但让 NANO 53MB / SMALL 44MB 区长期处于高位，且与 15% CPU 互为因果：

1. **KaraokeLabel `fullTextWidth` 每 0.25s 新建 CTFramesetter 不缓存**：`LyricsRendering/KaraokeLabel.swift:167-173`（同文件 :129-156 `_ctFrame` 明明有缓存模式）——播放中每 0.25s 一次完整文本 shaping（LyricsEngine.swift:711 playbackTimer 驱动）。
2. **ruby 注音每帧重建**：`KaraokeLabel.swift:465-501` 每次 draw() 重建 NSAttributedString + 测量 + CTLine；draw 由 30fps 定时器（:355）驱动。
3. **marquee 60fps + 每 0.25s 重建 timer**：`LyricsTouchBarItem.swift:371`（fps=60 :25）+ `:316-321` startMarquee 每 0.25s invalidate+重建 → 每次重建分配 CAAnimation/timer 对象。

**低风险修复**：缓存 fullTextWidth（与 _ctFrame 同生命周期）、ruby CTLine 预计算、marquee fps 60→30 且"timer 已存在则复用"。

## 六、结论与优先修复排序（全部低风险、行为无关）

| 优先级 | 动作 | 文件:行号 | 预期回收 |
|---|---|---|---|
| **P0-1** | 关窗即释放设置窗口（`AppDelegate.swift:143` 改 weak / windowWillClose 回调置 nil） | AppDelegate.swift:143,157-158 + UnifiedSettingsWindowController.swift:133-137 | **~170MB**（136 CA + SwiftUI 图 + 缓冲大头），并停掉 15% CPU |
| P0-2 | Deck.Background repeatForever 挂 isVisible 暂停 | UnifiedSettingsWindowController.swift:437-441（参照 :1113） | 停止 60fps 离屏渲染（CPU 归零 → 抖动内存也归零） |
| P0-3 | 去掉两处 `.blur(radius:5)` 改静态 | :427, :435 | 24~30MB backing |
| P0-4 | SettingsTabCache 加 LRU（3~5 tab） | :886-892 | 缓存视图图缩至活跃 tab |
| P1-5 | marquee 两缺陷 + fps 60→30 | LyricsTouchBarItem.swift:279-285,316-321,371 | 减 timer/动画对象抖动 |
| P1-6 | 缓存 fullTextWidth + ruby CTLine 预计算 | KaraokeLabel.swift:167-173,465-501 | 减 0.25s/帧的 CT 分配 |
| P2-7 | 实现 didReceiveMemoryWarning：SettingsTabCache.removeAll + CoverCache 清理 + URLCache 清理 | AppDelegate.swift（新增） | 系统压力时兜底（当前 0 响应） |

**预期效果**：P0 全部落地 → 物理内存 304MB → **~150-170MB**，CPU 15% → <3%。验证方法：改后开一次设置再关闭，`footprint <pid>` 看 CoreAnimation 是否从 136MB 回落到几十 MB、`heap <pid>` 看 SettingsRootView/AGSubgraph 是否消失。

**风险**：均为生命周期/频率/缓存改动，不改变 Touch Bar 外观与交互；唯一注意点是"关窗释放"后设置窗口未保存状态（windowShouldClose :139-157 已有保存提示，不受影响）。
