## 一、实测证据（运行中的 app，PID 971）

| 指标 | 实测值 | 说明 |
|---|---|---|
| CPU | 14.2%（ps 衰减均值）；**15.3~15.6%** 采样落在 `com.apple.SwiftUI.DisplayLink` 队列 | sample 两次（5s / 20s）比例稳定，与用户报的 15% 完全吻合 |
| 物理内存 | 304.2MB（peak 322.1MB） | 低于峰值 → 稳定平台期，**不是无限泄漏，是"占着不还"** |
| CoreAnimation | **136MB / 1023 regions** | 占总内存 45%，离屏渲染堆积 |
| MALLOC | NANO 53 + SMALL 44 + TINY 27 + MEDIUM 6 ≈ 130MB | 瞬时对象抖动 + 常驻对象 |
| 窗口 | 唯一 onscreen 是菜单栏图标；**「设置」窗口（980×660）offscreen 但存在**（onscreen=false, alpha=1.0），popover 窗口（352×606）同样离屏常驻 | 幽灵窗口实锤 |
| 主线程 | 大量 CAAnimation dealloc 抖动（动画对象每帧创建/释放） | 与 repeatForever 动画吻合 |

**CPU 去向定位**：采样栈为 `NSHostingView.startAsyncRendering → renderFromAsyncDisplayLink → ViewGraph.updateOutputsAsync → AG::Subgraph::update` —— 即某个 SwiftUI 视图树在以 60fps 持续重绘。结合窗口列表，就是**那个已"关闭"、实际还活着的设置窗口**。

## 二、根因链（核心结论）

```
用户打开设置 → 关闭窗口
   ↓
AppDelegate.swift:143 强持有 unifiedSettingsController（:157-158 创建后永不置 nil）
   ↓
windowWillClose（UnifiedSettingsWindowController.swift:133-137）只清 weak static current
   → 窗口 / NSHostingView / 整棵 SwiftUI 视图树永不释放
   ↓
UnifiedSettingsWindowController.swift:437-441 全项目唯一的 repeatForever 动画
（Deck.Background 两个 700×700 / 620×620 带 .blur(radius:5) 的 RadialGradient 漂移）
不订阅任何可见性状态 → 永不停止
   ↓
SwiftUI DisplayLink 持续 60fps 渲染不可见窗口 = 15% CPU
   ↓
离屏渲染不断产生 CA backing store / IOSurface + 21 个 tab 图层树全量驻留
（SettingsTabCache :886-892 缓存所有访问过的 tab，ZStack :1119-1127 全量挂载）
+ 19 处 .shadow 离屏层 + 每帧失效重渲的 blur
= 136MB CoreAnimation / 1023 regions
```

一句话：**关掉设置窗口 ≠ 释放设置窗口**。窗口带着整棵"夜店风"图层树和永不停歇的动画在后台偷偷渲染，CPU 和内存同时被它吃掉。

## 三、分项发现（按对日常使用的贡献排序）

### P0-1 设置窗口幽灵渲染 —— CPU 15% + CoreAnimation 136MB 的唯一主因
- 强持有：`App/AppDelegate.swift:143` `private var unifiedSettingsController: UnifiedSettingsWindowController?`；`:156-167` openSettings 仅 nil 时创建，**全文件无置 nil 路径**。
- 关闭只清弱引用：`Preferences/UnifiedSettingsWindowController.swift:95`（weak static）+ `:133-137`。
- 动画不暂停：`:437-441` repeatForever；对比作者已给别的动画做暂停（Equalizer `:1113` `paused: !windowState.isVisible`；歌词预览 `LyricsTabView.swift:1057-1058`）——**唯独漏了 Background**。
- 图层驻留：`:886-892` SettingsTabCache 缓存全部访问过的 tab（AnyView 强持有）+ `:1119-1127` ZStack 全量挂载 → 1023 regions。
- 每帧重渲的 blur：`:421-436` 两个大 RadialGradient `.blur(radius: 5)`，blur 内容每帧变化无法缓存，源+目标双 backing ≈ 24~30MB 常驻。
- 19 处 `.shadow(`（Card :472 / Pill :548 / NavItem :1212 等），每处一个离屏 shadow 层。

### P0-2 歌词渲染每 tick / 每帧重建 —— MALLOC 抖动源（CPU+内存双烧）
- `LyricsRendering/KaraokeLabel.swift:167-173` `fullTextWidth` 每次调用新建 CTFramesetter + suggestFrameSize **且不缓存**（同文件 :129-156 `_ctFrame` 明明有缓存模式）；被 `LyricsTouchBarItem.swift:297` 每次 onLyricsUpdate 调用，而引擎每 **0.25s** 发布一次（`LyricsIntegration/LyricsEngine.swift:711` playbackTimer）→ 播放中每 0.25s 一次完整文本 shaping。
- `KaraokeLabel.swift:465-501` ruby 布局（romaji 注音）每次 draw() 重建 NSAttributedString + 测量 + CTLine；draw 由 **30fps 定时器**（:355）驱动 → 开启注音时每帧全量重建。
- 对比（已做对的，勿回退）：高亮 CTFrame 缓存 `_progressCTFrame`（:277）、每行只重建一次的 setProgressAnimation（:215-282）。

### P0-3 歌词 marquee 60fps —— 日常播放时几乎常驻 + 两个缺陷
- `LyricsTouchBarItem.swift:371`，`MarqueeMetrics.fps = 60`（:25）。普通 LRC 行（无逐字时间标签）播放时**常驻 60fps**，Touch Bar 不可见也照跑。
- 缺陷 A（暂停不停）：暂停分支（:279-285）只暂停进度动画，**不 stopMarqueeTimer** → 暂停时空转。
- 缺陷 B（0.25s 回跳）：每 0.25s playbackTimer 经 Combine 链重进 handleTextScroll → startMarquee（:316-321）→ invalidate + 重建 timer + `marqueeStartTime = Date()` 重置（:369）→ 滚动每 0.25s 跳回起点，视觉反复回跳 + 每 0.25s 一次 timer 重建。

### P1-4 脚本按钮每 5s fork `top -l 2`（用户激活配置中实际在跑）
- `Core/AppleScriptTouchBarItem.swift:49` 递归 asyncAfter 每 5s 执行一次 `top -l 2` 系列命令（3 个子进程），每次瞬时 CPU/IO 峰值。5s 间隔过密，且在主线程同步 fork。

### P1-5 TouchBarController 每次切应用全量重建 items
- `Core/TouchBarController.swift:337-339` didLaunch/didTerminate/didActivate 三个通知全指向 updateActiveApp()；`:448-497` **无 `guard appDidChange` 快速路径**，默认配置（freezeOnAppSwitch=false）下每次前后台切换都 `prepareTouchBar()` → `createItems()` 全量销毁重建（:623-682）。与主线程 CAAnimation dealloc 抖动互相印证。

### P2-6 无任何内存警告响应
- 全仓 grep `didReceiveMemoryWarning` / memory pressure 0 命中；`SettingsTabCache` 无上限、CoverCache 无 eviction 钩子。

## 五、优化路线图（按收益排序，每项可独立落地）

### P0（预计回收绝大部分 CPU + 内存，改动小）
1. **关窗即释放设置窗口**（最大单项，预计回收大部分 136MB CoreAnimation + 停止 15% CPU）：
   `AppDelegate.swift:158` 改为在 `UnifiedSettingsWindowController.swift:133` windowWillClose 里回调置 `unifiedSettingsController = nil`；或直接把 `AppDelegate.swift:143` 改 `private weak var`（openSettings :157 的 nil 判断会自动重建）。窗口释放 → DisplayLink 停止 → 15% CPU 归零。
2. **暂停 Background repeatForever**：`Deck.Background`（:416-443）加 `@ObservedObject windowState = SettingsWindowState.shared`，不可见时停动画（复用 :1113 Equalizer 的 paused 模式）；或去掉 repeatForever 改静态渐变。
3. **marquee 修两缺陷**（`LyricsTouchBarItem.swift`）：① 暂停分支（:279-285）补 `stopMarqueeTimer()`；② startMarquee（:316-321）加"timer 已存在则复用"判断，仅行切换时重建 → 同时消除 0.25s 回跳视觉 bug；③ fps 60→30（触摸条肉眼无差）。
4. **缓存 fullTextWidth**（`KaraokeLabel.swift:167-173`）：与 `_ctFrame` 同生命周期缓存，消除每 0.25s CTFramesetter 重建。

### P1（进一步削减）
5. **去掉两处 `.blur(radius: 5)`**（:427, :435）：静态模糊纹理启动时预渲染一次，动画只做 opacity/transform → 消除每帧 blur 重渲（省 24~30MB backing + 每帧重渲）。
6. **削减 shadow**（重点 Card :472 / Pill :548 / NavItem :1212）：每处 shadow = 一个离屏层。
7. **脚本按钮 5s→≥15s**（`AppleScriptTouchBarItem.swift:49`），或改后台队列的 TBPollItem 避免主线程 fork。
8. **TouchBarController 加快速路径**：updateActiveApp（:448）加 `guard appDidChange` / touchBarIsBuilt 判断，应用切换不再全量重建。
9. **SettingsTabCache 加 LRU**（:886-892）：只保留最近 3~5 个 tab；暴露 removeAll() 给内存警告。
10. **ruby CTLine 预计算**（`KaraokeLabel.swift:465-501`）：布局时算好 CTLine，draw 只 CTLineDraw。

### P2（健壮性）
11. **实现 `applicationDidReceiveMemoryWarning`**：清 SettingsTabCache + CoverCache.memoryCache + URLCache。
12. **isVisible 全量可见性通知**：`SettingsWindowState` 改监听 NSWindow didOrderOut / willMoveToWindow 等，任何隐藏路径都复位（防未来新动画再踩坑）。
13. **NetEase 歌词小型 LRU**（可选）：省换歌重复下载+解析。

## 六、预期效果与验证

| 指标 | 当前 | 修复 P0 后预期 | 全部落地后 |
|---|---|---|---|
| CPU | 14~15% | **< 3%**（DisplayLink 停止，仅剩歌词 30fps 与低频轮询） | ~1-2% |
| 物理内存 | 304MB | **~170MB**（释放设置窗口图层树 + blur backing） | ~150MB 内 |
| 歌词滚动 | 0.25s 回跳 + 暂停空转 | 滚动顺滑、暂停即停 | — |

**验证方法**：改完后打开一次设置 → 关闭 → `sample <pid> 10` 看 SwiftUI DisplayLink 是否消失；`footprint <pid>` 看 CoreAnimation 是否回落到几十 MB。日常使用复测：播放一首普通 LRC 歌曲观察歌词滚动不再回跳、暂停播放后 CPU 明显下降。

**风险**：均为行为无关改动（生命周期/频率/缓存），不改变 Touch Bar 外观与交互；唯一注意点是"关窗释放"后设置窗口的未保存状态（windowShouldClose :139-157 已有保存提示，不受影响）。
