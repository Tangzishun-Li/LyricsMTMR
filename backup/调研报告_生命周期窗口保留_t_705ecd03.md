# LyricsMTMR 生命周期/窗口保留 调研报告（t_705ecd03）

> 只读调研，未修改任何仓库源码文件。仓库路径：`/Users/litz/codespace/MTMR with LyricsX /LyricsMTMR/MTMR`（注意尾随空格）。

## 结论摘要

**假设完全成立**：设置窗口关闭后，`AppDelegate` 强持有 `unifiedSettingsController`，窗口+NSHostingView+SwiftUI 视图树永不释放；全项目**唯一**的 `repeatForever` 动画（`Deck.Background`）不订阅任何可见性状态，持续驱动 SwiftUI DisplayLink 以 60fps 渲染离屏窗口，是 ~15% CPU 的主源。另发现同类问题 4 处。

## 发现 1（核心，假设确认）：设置窗口关闭后永不释放 → 离屏 60fps 渲染

## 发现 2：SettingsTabCache 放大泄漏
- `UnifiedSettingsWindowController.swift:886-892` SettingsTabCache 强持有 `[SettingsTab: AnyView]`；`:900` `@State` 持有；`:1140-1155` 访问过的 tab 永久缓存
- 后果：窗口不释放 → 所有访问过的 tab 视图树+模型常驻（RibbonEditorView `RibbonEditorView.swift:833`、@StateObject RibbonModel `:834`、TouchBarSimulatorView `TouchBarSimulatorView.swift:56`、PropertiesInspectorView），304MB footprint 的重要构成

## 发现 3：其他强持有对象
- **3a statusPopover**（`AppDelegate.swift:25,76-84`）：常驻设计，无持续动画（StatusBarMenuView 仅 hover），仅内存不烧 CPU；CGWindowList 显示关闭后 offscreen popover 窗口（352×606）仍存在。低危。
- **3b TouchBarMirrorWindowController**（`Core/TouchBarMirrorWindowController.swift:3-9,76-81`）：singleton 强持有 window/stackView/mirrorItems；hide() 仅 orderOut+invalidate timer，不释放视图树。默认关闭（`AppSettings.swift:153` defaultValue:false）。低危。
- **3c RibbonEditorView/PropertiesInspectorView/TouchBarSimulatorView**：SwiftUI 结构体，无独立窗口，生命周期随 Editor tab 被 TabCache 缓存 → 归入发现 2。

## 发现 4：DockVisibilityManager / SettingsWindowState 覆盖不到 repeatForever
- **4a 结构性**：SettingsWindowState（`:17-25`）isVisible 更新点仅 `:161-171,135`，靠视图主动订阅才生效；repeatForever 隐式动画无暂停 API，必须显式替换/移除。DockVisibilityManager（`:32-90`）只管 activation policy，与渲染无关。
- **4b 附带 bug**：`track(window:)` 只在 controller init 调用（`:117`）；windowWillClose 里 `handleSettingsWindowClosed()`（`:50-54`）removeObservers（`:71-74`）；AppDelegate 复用同一 controller（`AppDelegate.swift:157-160`）→ **第二次打开时不再 track** → observers 缺失，Dock 图标状态不再同步；关闭后 policy 停留在 .accessory，再打开不恢复。

## 发现 5：TouchBarController 频繁全量重建 items（默认路径）
- `Core/TouchBarController.swift:337-339`：didLaunch/didTerminate/didActivate 三个通知全指向 `updateActiveApp()`——任何应用启停/激活都触发
- `:448-497`：**无 `guard appDidChange else { return }`**；非 frozen 默认路径（`AppSettings.swift:156-157` freezeOnAppSwitch 默认 false）无条件 `prepareTouchBar()`（`:490`）
- `:384-396` prepareTouchBar 无条件 `createItems()`（`:396`）；`:623-670` 全量销毁重建所有 item（`discardCurrentItems` `:675-682`）
- `:410-414` didItemsChange 只跳过布局重建，createItems 已执行完
- 佐证：sample 主线程大量 CAAnimation dealloc 抖动；`:713-716` 作者注释自认 createItems 昂贵但常规路径不用 presentTouchBarWithCurrentItems

## 优化建议

1. **修核心泄漏**：`App/AppDelegate.swift:143` 改 `private weak var unifiedSettingsController: UnifiedSettingsWindowController?`。关闭后全链释放、DisplayLink 停止；`:157` nil 判断自动重建。DockVisibilityManager `:51` 已置 trackedWindow=nil 不阻断释放。
2. **停 repeatForever（覆盖最小化场景）**：`Deck.Background`（`:416-443`）加 `@ObservedObject windowState = SettingsWindowState.shared`，把 withAnimation repeatForever 换成 `TimelineView(.animation(minimumInterval: 1/30, paused: !windowState.isVisible))` 计算 drifting（仿 `:852-861` Equalizer 模式）。
3. **修 Dock 同步 bug**：`AppDelegate.swift:156-167` openSettings 中 showWindow 前加 `DockVisibilityManager.shared.track(window: w)`；track（`:43-48`）幂等化（`if trackedWindow === window { return }` 或先 removeObservers）。
4. **TabCache**：随 ① 修复自动释放；可选在 windowWillClose 清缓存。
5. **TouchBarController**：`updateActiveApp()`（`:448`）在 `lastSeenAppId = currentAppId` 后加快速路径：
```swift
if !appDidChange, !isAutoSwitched, touchBarIsBuilt() {
    if let appId = currentAppId, blacklistAppIdentifiers.contains(appId) { dismissTouchBar() }
    else { presentTouchBar() }
    return
}
```
6. **低优先级**：`TouchBarMirrorWindowController.hide()`（`:76-81`）追加 `window = nil; stackView = nil; mirrorItems.removeAll()`；statusPopover 常驻可接受。
